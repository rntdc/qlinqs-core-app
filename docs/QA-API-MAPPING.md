## Check 2 — Regras de validação (doc §2) — PASS

`PageContentRules`, `PageThemeRules` e `StyleOverrideRules` lidos e comparados
com o doc, tabela por tabela e caminho por caminho:

- **`PageContentRules` (verbatim)** — todas as regras do doc conferem com o
  código: `header required|array`, `header.name required|string`,
  `header.bio nullable|string`, `socialIcons present|array` (pode ser vazio),
  `socialIcons.*.platform/value required|string`, `blocks present|array`,
  `blocks.*.id required|string`, `blocks.*.kind required` enum
  `["atomic"]` (`"container"` → **422 confirmado live**), `blocks.*.type`
  enum `["link","whatsapp","maps","text","heading"]`, `blocks.*.layout`
  **condicional**: enum `["button","thumbnail","featured"]` apenas quando
  `type==="link"` (whatsapp com layout livre "banana" → **200 live**), demais
  `required|string`; `blocks.*.hidden required|boolean`;
  `blocks.*.card present|array` (pode ser `{}` — aceito live);
  `card.title/description/buttonText/label` nullable|string;
  `card.link nullable|array`, `card.link.kind` required-with enum
  `["url","email"]`, `card.link.href` required_with string;
  `card.image nullable|array` com `image.source` required_with enum
  `["upload","icon","emoji"]` + `value` required_with string;
  `card.overrides nullable|array`.

- **`blockDefaults`/`card.overrides` (StyleOverrideRules)** — `align`/`size`
  (enum left/center/right | large/small) permitidos apenas em
  `card.overrides`; **proibidos em `blockDefaults`** (→ 422 confirmado live,
  `The blockDefaults.align field is prohibited.`). Doc §2 nota isso de forma
  "doc says our choice, build against it" — bate com "proibidos no theme,
  no código".

- **`PageThemeRules` (verbatim §3)** — `page required|array`,
  `page.header required|array` + `layout enum ["classic","business"]`,
  `page.background required|array` + `type enum ["none","solid","gradient"]`,
  `page.profilePicture present|array`; `blockDefaults present|array` (sem
  align/size, como acima), `fonts present|array` com titleFont/textFont
  nullable|string; `palette required|array` com os 6 campos
  background/text/surface/onSurface/accent/onAccent **todos
  `required|string`** — conforme doc ("todos obrigatórios, sempre").
  Confirmado live: enviar `palette` faltando `onAccent` → **422**
  (`The palette.onAccent field is required.`).

- **Minimal examples** — ambos os exemplos do doc (content minimal: header
  name + socialIcons [] + blocks []; /theme minimal com palette completa)
  passam `Validator::make(...)->passes()===true` E pasam `PUT` live com 200.
  (Probes D2/D3 deste QA).

Sem regras extra/missing em relação ao doc. Pontos "plain-language summary"
do doc (§2.4) verificados: `card.image` nunca requer VALUE dedo sem card,
exclusividade de enums, etc. — tudo fiel.

## Check 3 — Validação de conteúdo/theme (docs §3) — PASS (com nota §3.3)

PUT /api/page/content e /api/page/theme: 200 para payloads válidos (idem
minimal), 422 com `errors` (object Laravel) quando rule falha — 200 live com
422 retorno, 404 quando `teste` tem página/`demoPage()` não acha. Probes
confirmando os casos-limite do doc §3.3:

- container `kind` → 422 (enum atomic-only) ✓
- link `layout:"banana"` → 422 (enum link-only) ✓
- whatsapp `layout:"banana"` (não-link) → **200** (doc: enum confinado a link) ✓

- `blockDefaults.tactile:"glass"` + `border:50` + `shadow:80` + `shadowStyle`

  by validator; render-time concern" ✓
- `blockDefaults.align` → 422 (prohibited) ✓
- `palette` sem `onAccent` → 422 ✓
- cores não-hex (`"purple-ish"`) → **200** (doc: cor = string livre, sem

Nota (§3.3, registrada como identicada, não como falha): o `422 ErrorsMessage`
do Scramble apenas documenta 422 para os dois PUTs; o `404` não aparece em

- `GET /api/user` → 401 sem token (auth:sanctum); **nenhum fluxo de emissão
  de token** (sem login/register) — doc §6.7 verdadeiro.

## Check 5 — Persistência behaviour (doc §5 / §2.5 "important") — PASS

Live probes de PUT + readback (via GET e via psql) confirmam **exatamente** o
"Persistence behaviour — not just whatever-validates-gets-saved":

1. **Nested unknown keys preserved** — enviado `blocks.[].card.extra`,
   `header.sheetColor`, `card.extra` (arbitrários) → 200; GET de volta inclui
   todos. ✓
2. **Top-level unknown keys dropped** — enviado `"hack":1` no topo → não
   salvo (ausente no readback), mas payload ainda 200 (drop silencioso). ✓
3. `Arr::only($request->all(), ['header','socialIcons','blocks'])` nos
   controllers — **confirmado no source** (não `$request->validated()`; o doc
   adverte "don't clean this up"). ✓
4. Só chaves topo documentadas persistem; como o doc diz, sem snapshot FKs
   de templates (apply copia theme, não referencia). ✓

## Check 6 — Route + Scramble discrepancies (doc §6) — PASS

Licenças/rotas do endpoint — tudo conferência ao vivo:

1. **404 ausente no spec**: GET /api/page, PUT content, PUT theme → spec
   Scramble só lista 200 (+422 p/ os PUTs). Confirmado no `api.json`:
   `/page` resp codes = `['200']`, `/page/content` = `['200','422']`,
   `/page/theme` = `['200','422']` — **sem 404**. ✓
2. **`GET /api/templates` — schema errado no Scramble**: componente
   `Template` marca `created_at` como required+propriedade; resposta live
   nunca inclui `created_at`. Confirmado (live templates sem created_at;
   spec Template required inclui created_at). ✓
3. **`blockDefaults.align/.size` documentados como strings livres** no spec;
   na realidade **422 (prohibited)**. Confirmado. ✓
4. **`page.profilePicture` documentado como `string[]`** no spec; na realidade
   `present|array` (objeto arbitrário). Confirmado via schema live. ✓
5. **`content`/`theme` genéricos** (`{"type":"array","items":{}}`) em todas
   as respostas de page — o §2 do doc é a shape autoritativa. Confirmado. ✓
6. **404 de `/p/{slug}` rotulado como `ModelNotFoundException`** no spec;
   na verdade mensagem custom (`abort_unless`). ✓
7. **`GET /api/user`** documentado como alcançável (200/401) sem rota de
   emissão de token — nenhum login/register existe. ✓

**Sem discrepância omitida** — criei um scan independente do `api.json`
